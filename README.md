# TLV ⇄ Europe — מעקב מחירי טיסות ומלונות

סורק את המחירים הזולים ביותר מתל אביב לכ-33 יעדים באירופה, שומר היסטוריה, ומתריע בטלגרם כשמופיע מחיר טוב משמעותית מהחציון ההיסטורי. רץ אוטומטית כל 6 שעות דרך GitHub Actions, ומציג דשבורד חי ב-GitHub Pages.

## שלב 1: הרשמה ל-Travelpayouts (חינם)

> עדכון: התוכנית המקורית התבססה על Amadeus, אבל הם סגרו את פורטל ה-Self-Service לגמרי ב-17 ביולי 2026. המקור החלופי כאן — Travelpayouts / Aviasales Data API — פתוח להרשמה עצמאית וחינמי ללא מינימום משתמשים.

1. הרשמה: https://www.travelpayouts.com/en/join?type=api (או הכפתור "Sign up" ב-https://www.travelpayouts.com)
2. אחרי אימות המייל, היכנסו לפרופיל וקבלו את הטוקן: https://app.travelpayouts.com/profile/api-token
3. תעתיקו את ה-**API Token** — זה הערך היחיד שצריך (אין Key+Secret כמו ב-Amadeus).
4. תיעוד מלא אם תרצו להעמיק: https://travelpayouts.github.io/slate/#about-api

> המחירים מגיעים ממטמון של חיפושים אמיתיים באתרי Aviasales (עדכניים עד 7 ימים אחורה) — מצוין לזיהוי מגמות ומחירים חריגים, אבל לפני הזמנה בפועל תמיד כדאי לוודא מול Google Flights/האתר עצמו.

## שלב 2: מציאת ה-chat_id שלכם בטלגרם

יש לכם כבר טוקן לבוט. עכשיו צריך את ה-chat_id:

1. שלחו כל הודעה לבוט שלכם בטלגרם (חפשו אותו לפי השם שנתתם לו ביצירה עם BotFather).
2. גשו בדפדפן ל-`https://api.telegram.org/bot<הטוקן שלכם>/getUpdates`
3. חפשו בתשובה `"chat":{"id": 123456789, ...}` — זה ה-chat_id.

## שלב 3: הקמת הריפו ב-GitHub

1. צרו ריפו חדש (יכול להיות פרטי) והעלו אליו את כל הקבצים מהתיקייה הזו.
2. **Settings → Secrets and variables → Actions → New repository secret**, והוסיפו 3 secrets:
   - `TRAVELPAYOUTS_TOKEN`
   - `TELEGRAM_BOT_TOKEN`
   - `TELEGRAM_CHAT_ID`
3. **Settings → Actions → General → Workflow permissions** → סמנו **Read and write permissions** (כדי שה-Action יוכל לשמור את נתוני ההיסטוריה בחזרה לריפו).
4. **Settings → Pages** → Source: **Deploy from a branch**, Branch: `main` / `root`.
5. **Actions** → תראו את הוורקפלואו "Scan flight & hotel prices" → אפשר להריץ ידנית עם **Run workflow** כדי לבדוק שהכל עובד לפני שממתינים ל-cron.

הדשבורד יופיע בכתובת `https://<username>.github.io/<repo-name>/`.

## איך לעדכן תאריכים

ערכו את `config/settings.json`:

- `departureDate` / `returnDate` — התאריכים שתרצו לבדוק.
- `flexible: false` — יבדוק רק את התאריכים המדויקים האלו.
- `flexible: true` + `flexDays: 3` — יבדוק גם ±3 ימים סביב כל תאריך ויבחר את הזול ביותר בטווח.
- `discountThresholdPercent` — כמה אחוז מתחת לחציון ההיסטורי כדי שתישלח התראה (ברירת מחדל 20%).
- `maxPriceILS` — תקרת מחיר אופציונלית; גם אם יש הנחה טובה, לא תישלח התראה מעל המחיר הזה.

כל שינוי בקובץ הזה נכנס לתוקף בריצה הבאה (מיידית אם תריצו ידנית מה-Actions).

## איך זה עובד מאחורי הקלעים (לחיסכון במכסת ה-API)

1. לכל יעד: קריאה **אחת** ל-`/v2/prices/week-matrix` — מחזיר מחירי Round-trip אמיתיים בטווח של שבוע סביב התאריכים שהזנתם (3 ימים לפני עד 4 ימים אחרי). אם `flexible=true` נבחר המחיר הזול ביותר בטווח; אם `false` מחפשים את התאריך המדויק.
2. הדירוג של כל 33 היעדים נעשה על בסיס המחיר הזה ישירות מול החציון ההיסטורי שלו.
3. רק ל-5 היעדים המובילים (`checkHotelsForTopDeals`) מתבצעת קריאה למחיר מלון (Hotellook, אותו טוקן).
4. היסטוריית מחירים (`data/history.json`) נשמרת לכל יעד, ומשמשת לחישוב "חציון היסטורי" להשוואה.

כך כל ריצה צורכת כ-33+5 = כ-38 קריאות API — מתחת למגבלת הקצב (300 בקשות/דקה) בנוחות, גם בריצה כל 6 שעות.

## מגבלות ידועות

- הנתונים מגיעים ממטמון חיפושים אמיתיים (לא Live Pricing חי כמו הזמנה בפועל) — מעולה לזיהוי מגמות ומחירים חריגים, פחות מדויק ל"שנייה האחרונה".
- מחיר המלון (Hotellook) הוא שכבת בונוס; אם החשבון החדש עדיין לא מקושר לתוכנית Hotellook, ייתכן שיחזור ריק — זה לא משפיע על התראות הטיסות.
- אין קישור הזמנה ישיר בהודעת הטלגרם כרגע — ההתראה נותנת יעד + תאריכים + מחיר; אפשר להוסיף בהמשך קישור שותפים (`link`) שה-API מחזיר.
